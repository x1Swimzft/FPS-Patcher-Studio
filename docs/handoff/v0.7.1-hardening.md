| `src/fps_patcher/core/colr.py` | Whitelist known visual sample entries; preserve unsupported entries raw and do not tag them; validate pre-`moov` chunk offsets against every `mdat`; validate offsets even when `delta == 0`. | `stsd` parsing assumed every entry was a 78-byte `VisualSampleEntry`; pre-`moov` offsets were skipped without a range check. |

## Measurements

Environment: Windows NT 10.0.26200, Intel i5-13500, 34 GB RAM, Python 3.11.17, local NTFS, warm cache. Harness: `uv run python tools/bench_audit.py`, three warm runs after the changes. The comparable warm baseline re-measure was `638.6 ms` for 2000 queue adds; the original audit's `1069 ms` was an earlier baseline run and is not used for the ratio.

|---|---|---|

The queue improvement comes from reducing `Path.resolve()` calls from **4 to 1** per new path. The watcher's processed-file fast path (no `O_RDWR` lock probe after delivery) is covered by a unit test; this microbenchmark scans fresh files, so it does not show that gain. The benchmark does not isolate the new job/mutex cost; each patch adds one destination-lock acquire.

- **Real MP4/MOV**: `sanitize` roundtrip on ffmpeg-generated MP4 (30 fps) and MOV (59.94 fps); every `mdat` payload SHA-256 unchanged, chunk offsets still inside an `mdat`, and ffprobe decodes more than zero frames.

- **Fragmented MP4**: `frag_keyframe+empty_moov` output is detected (`moof` present), returned as `skipped`, left byte-identical, and still decodes.

## Remaining risks and deliberate limits

1. **MP4 support is not universal.** `colr` handles a whitelist of known visual sample entries (`avc1`, `avc3`, `hvc1`, `hev1`, `mp4v`, `av01`, `vp09`). Unsupported entries are preserved raw and never tagged; if none are supported the result is `skipped`. Fragmented files (`moof`/`sidx`) are skipped before mutation. There is no `mdat` reconstruction.
2. **Chunk-offset validation checks the start offset only.** It verifies the offset lies inside an `mdat`, but not `offset + chunk_extent`, sample sizes, or trailing bytes. A corrupt file with an in-range start and out-of-range extent can still produce a bad output; the `moov` round-trip guard catches some, not all.
3. **Cross-process locking is Windows-only and `Local\` scoped.** It does not serialize across Windows sessions or across machines on a network share. `repair_for_mobile` still has no cross-process lock. `_DEST_LOCKS` grows one entry per distinct destination for the process lifetime (bounded by destinations used, not LRU).
4. **Shutdown is bounded, not guaranteed.** `controller.shutdown()` joins for at most 5 s; a stuck worker can outlive the window. `run_streaming` has no overall timeout (only cancel). The ffmpeg-locate probe thread is an untracked daemon. POSIX has no Job Object/parent-death equivalent, so cancel/hard-kill guarantees are Windows-only.
5. **Preflight startup sweep is folder-scoped.** It only scans folders known at startup (queued items, output dir, watch folder). Marked temps in other folders wait for a later run there or manual cleanup. Files without a valid marker are never deleted. PID-reuse and 60 s grace are heuristics.
6. **Payload-integrity FAIL is logged but does not block replacement.** `verify()` raises on structural failures, but a `verify_payload_integrity` FAIL only emits an ERROR log before `os.replace`. Making it a hard gate is a policy decision because BXD presets legitimately produce `EXPERIMENTAL` payloads.
7. **Coverage is generated media, not a device corpus.** No real camera/phone files, no real SMB/network-folder timing (the watcher test simulates a slow scan), and no long-running soak test beyond the repeated-job/temp/lock check.
8. **The packaged EXE is stale** relative to the latest source; the installer was not rebuilt or tested after these edits.
9. **Job assignment has a small spawn-to-assign window.** Descendants created before assignment are not retroactively added; ffmpeg spawns no helpers during that window today. `NamedMutex` abandoned-wait handling is best-effort.
10. **A non-blocking watcher stop can leave one scan running** on a daemon thread (network I/O only, no Tk calls); the delivery lock and inbox dedupe prevent duplicate patches, but the scan may finish after the window closes.

## Suggested next steps

- **Before release**: rebuild the EXE/installer from the final source and rerun the packaged smoke and installer checks.
- **Media corpus**: test real camera/phone MP4/MOV files, multiple-`mdat`/`co64` captures, and an SMB watch folder; add chunk-extent/trailing-byte validation if the corpus shows it matters.
- **Policy**: decide whether `verify_payload_integrity` FAIL should block `os.replace`; keep BXD `EXPERIMENTAL` outputs working if it does.
- **Locking**: extend the destination lock to `repair_for_mobile`; consider `Global\` or a file lock if cross-session/machine serialization is required.
- **Lifecycle**: add an overall watchdog for `run_streaming`, track/join the probe thread, and add a POSIX parent-death mechanism if POSIX becomes a target.
- **v0.8.0** (roadmap): IG Reels / YouTube Shorts presets and the 0–100 pre-flight score, fed by existing probe data.
- **v1.0.0** (roadmap): Nuitka native build, headless CLI, local IPC/REST; the atomic-output and shutdown work here are prerequisites for a long-running daemon.

## Operational notes

- Patcher temps look like `.<output-stem>.<random><ext>.part`; they are swept only when older than 24 h and matching that destination's name.
- Preflight temps look like `<source-stem>.preflight-<pid>-<hex><ext>` with a sibling `.<temp-name>.preflight-owner.json`. The startup sweep deletes only marked, stale, writable temps; unmarked files are never touched.
- Mobile-repair temps look like `.<output-name>.<random>.repair.tmp`; they are replaced into place on success and unlinked on the explicit verify failures. An unexpected exception can leave one behind.
- Output replacement is atomic on the same volume; the temp is created beside the destination.
- The destination lock covers final-name selection through `os.replace`; auto-rename is resolved under the lock. Same-base jobs serialize for the whole preflight/patch pass.
- Closing the window waits up to 5 s for the worker; the watcher is stopped without joining the Tk thread.
