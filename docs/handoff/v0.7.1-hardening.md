## What changed and why

| File | Change | Root cause |
|---|---|---|
| `src/fps_patcher/core/colr.py` | Per-entry `stco`/`co64` shifting; reject offsets inside `moov`; validate shifted offsets against every top-level `mdat` payload range. | One global shift corrupted mixed `mdat → moov → mdat` files. |
| `src/fps_patcher/core/patcher.py` | `mkstemp` temp in the destination dir, `os.replace()` swap, 24 h name-scoped stale-temp sweep, dry-run cleanup. | `unlink()+rename()` left a window with no output and fixed temp names could collide. |
| `src/fps_patcher/config.py` | Save lock, unique per-thread temp, atomic replace, log-and-keep-old on failure; destructive fallback removed. | Crash mid-write truncated the config; concurrent saves interleaved. |
| `src/fps_patcher/app/queue_model.py` | `set_info()` preserves `done`/`failed`. | Late probe results downgraded finished rows. |
| `src/fps_patcher/app/controller.py` | Clear `current` when the queue empties; `shutdown(timeout=5)` cancels and joins the worker. | Stale `current`; worker could outlive the window. |
| `src/fps_patcher/core/preflight.py` | Unlink partial temp on cancel/error. | Cancel left `.preflight` files behind. |
| `src/fps_patcher/ui/thumbnails.py` | FIFO memory cache bound at 128 entries. | Cache grew with every preview ever shown. |
| `src/fps_patcher/ui/input_list.py` | Prune `_ctk_images` / `_thumb_requested` on row removal and empty queue. | Per-row caches leaked after removal. |
| `src/fps_patcher/ui/main_window.py` | ffmpeg locate on a daemon thread; handle `ready`/`missing`; call `controller.shutdown()` on close. | 10 s subprocess probes on the Tk thread; worker not stopped at exit. |

## Measured behavior

See the audit's measurement table. Headlines: `sanitize` moves 256 MB at 621 MB/s with a 2.0 MB Python peak; a 2000-file watcher scan settles in 59 ms; thumbnail cache holds 128 entries after 1000 inserts; queue add costs 535 µs/file.

## Deliberate limits and remaining risks

1. **Fragmented MP4** (`moof`/`trun`) is skipped, not repaired.
2. **Non-visual/vendor sample entries** are assumed to use the 78-byte `VisualSampleEntry` layout; the `moov` round-trip guard refuses rather than corrupts, but there is no fixture for exotic entries.
3. **Concurrent patches to one destination** are atomic per write but last-writer-wins; no cross-process lock.
4. **Hard kill can orphan ffmpeg** — cancel kills the direct child, no Job Object / parent-death handling.
5. **Watcher stop joins up to 3 s on the Tk thread** on settings apply/close; typical join is ≤1 s, slow network folders can hit the cap.
6. **Preflight temps from a previous crash are not swept at startup**; only patcher temps are.
7. **`InputQueue.add()` resolves each path three times** (535 µs/file); not fixed because normal drops are small.
8. **Thumbnail cache is FIFO, not LRU.**
9. **`verify_payload_integrity` treats non-standard payloads as `EXPERIMENTAL`**, not FAIL, because BXD presets produce them by design.
10. **Not verified this session**: real-media smoke test, packaged EXE smoke test, network-folder watcher timing, hard-kill orphaning.

## Suggested next steps

- **v0.7.x**: Job Object for ffmpeg child processes; async watcher teardown; startup sweep for `.preflight` with an ownership marker; resolve-once in `InputQueue.add()`.
- **v0.8.0** (roadmap): IG Reels / YouTube Shorts presets and the 0–100 pre-flight score. Feed the score from the existing probe data; no new media parsing.
- **v1.0.0** (roadmap): Nuitka native build, headless CLI, local IPC/REST. The atomic-output and shutdown work here are prerequisites for a long-running daemon.

## Operational notes

- Temp files created by the patcher look like `.<name>.fps-XXXXXX.tmp` and are safe to delete when no patch is running; the app also sweeps ones older than 24 h.
- Output replacement is atomic on the same volume. Cross-volume output still copies to a temp beside the destination first, then replaces.
- Closing the window now waits up to 5 s for the worker; a cancel during a long ffmpeg run still returns promptly because the runner kills the child.
